# 微软玩家的 UUID 由 XUID 派生

非正版玩家的身份 UUID 取 `new UUID(0, xuid)`，而不是随机生成、也不是由名字派生。

理由有三层：

1. **身份锚定在微软账户而非名字**。玩家在客户端输入的名字是一段可以随意声称、可以随时间改变的文本；XUID 是微软分配的稳定标识。用名字派生 UUID 会让改名等于换号，用随机 UUID 则需要额外一张映射表才能回答「这个 XUID 之前是谁」。
2. **与 Floodgate 天然互操作**。`new UUID(0, xuid)` 正是 Floodgate 为基岩版玩家生成 UUID 的规则。这意味着同一个微软账户在 Java 直连和基岩版（Geyser）接入时会落到同一个 UUID 上，存档、权限、经济数据自然互通，不需要任何映射代码。选定这个规则后，将来接入基岩版无需迁移数据。
3. **不需要额外状态**。UUID 是 XUID 的纯函数，任何时刻都能从数据库里的一列 XUID 重算出来，不存在「UUID 与 XUID 不一致」这种需要修复的破损状态。

被否决的替代方案：随机 UUID 入库（与任何体系都不冲突，但 Floodgate 互操作要额外写映射，且多一列需要保持一致的状态）；名字派生的离线 UUID（兼容传统离线服，但改名即分裂数据，与本项目「不是传统离线服」的定位直接矛盾）。

注意这与「名字」层面的规则是分开的：一个 XUID 只能持有一个名字，但名字的变更不影响 UUID。
