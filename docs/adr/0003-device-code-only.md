# 认证只依赖服务端设备码，不做客户端模组

参考实现 xbridge-auth 的无感登录依赖一个客户端模组：模组在本机持有微软令牌，连接时把签名身份交给服务端。本项目不采用这条路线，只用微软 OAuth 的设备码流程。

理由：

- **xbridge 无法照抄**。它的 Modrinth 项目 `source_url` 为 `null`、许可证为 All-Rights-Reserved，CurseForge 上登记的 GitHub 仓库返回 404。没有协议规格可依赖，也就不存在「兼容它」这个选项。此外它自 1.0.1 起服务端只支持 Fabric，与 Paper 插件路线不兼容。
- **客户端模组要覆盖 1.8–26.3 的每个加载器**。Fabric 从 1.14 才开始，1.8–1.12 只能用 Forge，加上 NeoForge 与各版本间的映射差异，工作量与插件本体相当。
- **设备码不需要玩家安装任何东西，且在 1.8 到 26.3 的所有客户端上表现一致**。代价只是玩家要打开一次浏览器。

设备码流程的安全性由微软保证：玩家在微软自己的页面上输入凭据，服务器全程看不到密码；服务器轮询拿到的令牌只用于读取 XUID 与玩家代号，用完即弃、不入库、不保存刷新令牌。

由此产生的 UX 约束是强制的：玩家必须在能看见提示的地方等待验证。断线提示不可点击（原版所有版本的断线界面都是纯文本渲染，不处理 hover/click），所以链接只能出现在聊天框里——也就是玩家必须已经进入世界。这就是 Limbo 存在的原因。
