# 认证发生在进入世界之前，因此需要自研登录注入层

要让正版玩家零操作进服，插件必须在原版登录状态机认领这个连接之前介入：拦下 `Login Start`、自己发 `Encryption Request`、收到 `Encryption Response` 后向 Mojang 会话服务器复核 `hasJoined`、然后才把带着正确 UUID 的档案交回原版流程。

这层是自己写的，不依赖 PacketEvents 或 ProtocolLib：

- PacketEvents 的 Java 8 基线没有官方声明（它自称覆盖 1.7.10–26.3，但文档不写 JVM 要求），而本项目已经把 Java 8 设为不可协商的底线，引入一个基线未知的重依赖等于把整个项目的可行性押在别人的构建上。
- ProtocolLib 的正式版只测到 1.21，1.8–26.2 需要 Jenkins dev build，同样不适合作为唯一依赖。

自己的注入层只做三件事：在 pipeline 里插入一个 handler、解析/构造登录阶段的少量包、把各版本的 `GameProfile` 注入方式收敛到一个适配接口。包结构在 1.19（加签名与 UUID 字段）、1.20.2（配置阶段）、1.20.5（`shouldAuthenticate`）之间确实有变化，但收敛到登录阶段后变化面很小。

失败坐标是清楚的：如果某个版本的注入失败，症状是「该版本正版玩家无法自动登录」，而不是「整个插件加载不了」。这是选择自研的主要理由——故障是局部的、可定位的，而不是被依赖库的黑盒吞掉。
