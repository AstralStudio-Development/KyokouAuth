# 名字永久保留，且一个身份只能持有一个名字

两条规则，任何一条放松都会立刻产生冒充通道：

1. **一个 Name 永久属于至多一个 Identity。** 名字在客户端是自由输入的，如果允许多个 XUID 绑定同一个名字，第二个绑定的人就能以第一个人的 UUID 进服。
2. **被 Mojang 账户持有的 Name 永远不能绑定给 Microsoft Player。** 否则「先在一个正版玩家出现之前抢注他的名字」就是一条完整的冒充路径，且受害者永远进不来。

一个 XUID 同一时刻只能持有一个名字。改名默认仍走管理员指令；可显式开启 `verification.auto-rename`，允许持有人在新名字下重新完成微软设备码验证后迁移绑定。它不是添加别名：在同一个事务内检查新名字占用、更新身份资料并移动唯一名字，释放旧名；XUID、派生 UUID 和创建时间保持不变。写入失败则整体回滚，不得抢占其它身份或正版名字。旧在线连接不能继续使用被替换的名字。

正版身份优先于绑定：如果某个名字后来变成了 Mojang 账户（有人注册了它），已存在的 Microsoft Player 绑定即告失效，该玩家必须改名，不能以旧名字继续进服。优先级方向是单向的——正版名字永远赢。

非正版玩家无法预知某个名字将来是否变成正版名字；此时保留身份 UUID，通过管理员路径或显式开启的验证后自动改名路径迁移。自动改名关闭时，使用新名字验证同一 XUID 只会收到明确的旧绑定名提示，不得误报为“改名已完成，请重连”。
