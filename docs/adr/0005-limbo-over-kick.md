# 未认证玩家进 Limbo，不是被踢出

未通过认证的玩家会被放进世界（技能上就是正常 join），然后被冻结在原位、禁止移动/交互/聊天，屏幕上有验证码与可点击链接。验证通过后原地解冻；首次绑定因为 UUID 会变，需要重连一次。

为什么不是「踢出去，断线提示里给网址和验证码」：

- **原版断线界面的文本不可点击**。从 1.8 到 26.3，`DisconnectedScreen` 都是把 Component 逐行渲染成纯文本，不注册 hover/click 处理器。玩家只能手抄一个 8 位码和一条 URL 去邮箱或手机里输。这是可用性灾难，不是小瑕疵。
- **聊天框的点击事件是全版本可用的**。`ClickEvent(open_url)` 从 1.8 就在，配合 `microsoft.com/link?otc=<码>` 可以做到「点一下 → 浏览器已填好码 → 确认 → 回游戏时已经在世界里了」。

为什么不是独立虚空世界：玩家被冻结时看不到任何主世界内容，因此不需要一个额外的世界目录去隔离。原位冻结只多一件事——把玩家的原始位置存进插件自己的表，解冻时还原（因为 Bukkit 会在退出时把玩家当前座标写进 `playerdata`，冻结期间的座标会污染原位置）。

首次绑定必须在验证后重连一次，因为 UUID 是从 XUID 算出来的，而 XUID 在设备码完成前不可知。这是模型本身的约束，不是实现缺陷：临时 UUID 下的玩家数据在断开时删除，不参与任何后续逻辑。
