# v1 不做代理端模块，但会硬拒绝在代理后端运行

群组服里登录握手发生在代理端，后端根本看不到加密请求，因此在后端运行的认证插件无法完成 Mojang 握手。要让群组服工作，必须另写一个 Velocity 模块，认证在代理完成、后端只收身份。

v1 不做这个模块，理由是它属于另一条产品线而不是本项目的增量：认证状态、会话、Limbo 全部要重新设计一遍（代理端没有"世界"可以放 Limbo，需要用 hold connection 或单独的认证服）。

但**必须防止它被误用**：把本插件装在 `bungeecord: true` 的后端上，所有玩家都带着代理转发的身份进来，插件认为自己面对的是直连客户端，Mojang 握手会静默失败或误判。这不是"不支持"，是"会静默地变成不安全"。因此启动时检测 `spigot.yml` 的 `bungeecord` 设置与 Velocity 转发标记，检测到就拒绝启用并给出明确说明。
