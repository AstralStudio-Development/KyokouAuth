# 已废弃：1.8 支持不再是目标

**本 ADR 的结论已被 [0012](0012-minimum-version-1-12.md) 取代。** 保留它是为了记录一条被证伪的推理。

原文主张：支持 1.8 与「正版零操作登录」由同一件工作（Netty 登录注入层）卡住，所以应当一起做。

这个结论后来被推翻了两次：

1. **`setPlayerProfile` 的引入版本判断错了。** 原文写「1.8–1.12 上无法通过 Bukkit API 实现」，实测 `javap` 后确认 Paper **1.12.2 就有**该方法。受影响的只有 1.8–1.11。
2. **注入层不是 1.8 支持的前提。** 项目最终选择放弃 1.8–1.11，而不是为它建一套无法验证的 NMS 反射。注入层的价值只剩「正版零操作登录」，这也正是它现在做的事（见 [0010](0010-handshake-injection-status.md)）。

## 仍然成立的部分

- `AsyncPlayerPreLoginEvent#setPlayerProfile` 确实是选择 UUID 的唯一受支持途径。
- 引用 `PlayerProfile` 的类在缺少它的服务器上会加载失败，所以现代能力必须活在独立类里。
- Netty 注入层确实是「正版零操作登录」的实现方式。

## 被推翻的部分

- 「1.8 支持需要注入层」——不需要，需要的是放弃这个版本。
- 「1.8–1.12 都无法指定 UUID」——只有 1.8–1.11。

保留这条记录，是因为下次有人问「为什么不做 1.8」时，答案不是「技术上不可能」，而是「技术上要付的代价不值得，且我们已经明确选择了不做」。
