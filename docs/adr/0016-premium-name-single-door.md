# 正版名字只有一扇门：Mojang 握手

一个名字被 Mojang 持有时，进入服务器的方式**只有一种**——客户端完成 Mojang 握手。没有第二条路。

这一条推翻了本 ADR 早些时候的记录（当时允许正版玩家在握手不可用时走微软设备码兜底），也删掉了为那条兜底路写的一整套代码。

## 为什么兜底是错的

当时的理由听起来合理：玩家买了正版但启动器有问题，给他一条设备码路径，验证后照样能拿回真实 Mojang UUID，只是多点一次链接。

实际后果是：**一个离线客户端可以用着某个正版名字进入 Limbo，然后被绑定给完成那次设备码的任意微软账户**。这两件事之间没有任何强制关联——名字是客户端声称的，账户是浏览器里登录的。

这不是"边缘情况处理不当"，而是把身份的两个来源接在了一起：名字（不可信）和微软账户（可信）。用户的原话是「会出现很麻烦的情况」。

## 现在的判定顺序

先查名字归属，**再**查绑定状态：

```
名字被 Mojang 持有？
├─ 是 → 握手成功则进；否则立即断开，不进世界
└─ 否 → 微软设备码
```

之前是反的（先查绑定、后查名字），所以正版名能绕过名字检查走到设备码。顺序本身就是这次修复的核心。

## 三个连带删掉的东西

- **`Reason.PREMIUM_CLAIM`**：正版名不再有"验证中"这个状态。
- **`MinecraftServices` 整个类**：它只为"设备码后反查是否拥有 Java"而存在。留着就是对任何路径都不会执行的死代码，比删掉更危险——下一个读代码的人会以为存在第二条路。
- **`premium.prefer-handshake` 配置项**：它的"关闭"现在等于"正版玩家全部进不来"，是个陷阱。

## 一个被自己改动绊倒的 bug

删掉兜底后第一次实测：正版玩家被拒绝。

原因是我此前加过另一个优化——"有有效 IP 会话就跳过握手"。两者叠加后：

```
正版玩家连接 → 有会话 → 跳过握手 → 落入普通判定 → 名字是正版 → 拒绝
```

**曾经成功登录过的正版玩家第二次就进不来了。** 两个各自合理的改动，合起来是错的。这也是为什么每次改动后都要用真实客户端跑一遍——单元测试覆盖不到"两个层之间的假设冲突"。

那个优化已删除：握手对玩家不可见，成本只是两次接口调用，不值得拿正确性去换。

## 两种名字被占用的情形，回报不同

| 情形 | 玩家看到 | 管理员看到 |
|---|---|---|
| 陌生人用了别人的正版名 | "这个名字属于一个正版账号。" | 无（正常拒绝，不值得打扰） |
| **自己的名字被正版买走了** | "这个名字原本属于你……你的存档没有丢……请联系管理员改名" | **黄色警告 + 具体改名指令 + 受影响的 UUID/XUID** |

第二种是需要人工介入的运营事故：玩家自己是微软玩家，永远过不了握手，没有任何自助手段。不主动通知管理员的话，这件事只会表现为"某玩家突然进不来了"。

## 反向情形：正版玩家改名

正版玩家在 Mojang 改名后，握手会带来新名字，而库里存着旧名字。旧实现直接拒绝——于是：

- 玩家被锁在自己的账号外
- 旧名字被永久冻结（那行还占着主键），谁也拿不走

现在改为**跟随改名**：握手已经证明了这个客户端拥有该 Mojang UUID，对正版身份来说名字就是 Mojang 当前叫他的那个。UUID 不变、存档不动、旧名字释放。

## 代价，必须写明

正版名只有握手一条路，因此**握手装不上时，正版玩家全部进不来**。这只发生在一处部署前提上：

- 服务端不提供通道钩子（不是受支持的 Paper）

这种情况的启动提示是红色警告，明确写出"正版玩家将无法进服"。

**装 Floodgate 不再是其中一种。** 早前版本在检测到 Floodgate 时会让位、不装握手，依据是"Floodgate 对所有连接强制发起加密握手"。该依据已被证伪：Floodgate 只处理 handshake hostname 里携带加密 BedrockData 的连接，其余一律 `NOT_FLOODGATE_DATA` 放行，从不发 `Encryption Request`。实测在有 Floodgate 时，正版名连接收到的 `Encryption Request` 总数是 1 而非 2。详见 [ADR-0013](0013-integration-findings.md)。

让位的后果是把唯一的门拆掉——装了 Geyser 的服务器上正版玩家会永久进不来，而这正是本 ADR 要禁止的失效。因此现在两者同时安装，职责正交：Floodgate 认领 Bedrock 连接，我们认领 Java 正版名。
