# 它解决什么

离线模式（`online-mode=false`）下，服务端信任客户端自称的名字。

KyokouAuth 在登录阶段插入一层验证，要求每个连接先证明自己拥有一个微软账户：

| 玩家 | 验证方式 | UUID |
|---|---|---|
| 拥有 Java 版 | Mojang 握手，服务端完成 | 真实 Mojang UUID |
| 无 Java 版 | 微软设备码 | `UUID(0, xuid)` |

名字必须绑定到一个已验证的身份，绑定永久。被 Mojang 持有的名字只能由握手进入。

## 两条验证通道

### Mojang 握手

服务端向客户端发送加密请求，客户端用其会话令牌向 Mojang 确认，服务端再向会话服务器复核。流程与正版服务器相同，只是由插件在登录管线内自行完成。

验证成功后取得真实的 Mojang UUID 与皮肤。

### 微软设备码

服务端向微软申请一枚短码，玩家在任意设备上打开 `microsoft.com/link` 输入该码并完成登录，服务端轮询取得结果。

成功后取得 XUID，玩家的 UUID 由其派生为 `UUID(0, xuid)`。

## 约束

- 服务端必须是 `online-mode=false`
- 客户端不需要任何模组
- 不支持代理后端（检测到转发时拒绝启动）
- 最低 Minecraft 1.12
